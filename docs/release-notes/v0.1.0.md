# PerfStage v0.1.0

**Define once. Perform every time.**
**一次定义，次次上演。**

v0.1 是 PerfStage 的第一个可发布版本：在真机上一键跑完一次 Take——驱动 App、三 pass 录制、解析 trace、判定 `gate` 并出报告——并且把「哪些事属于平台、哪些事属于项目」写清楚。

## 包含范围

- **Runner**：`run_performance_test` 一条调用完成设备动作、录制、解析、收尾与报告。
- **CLI**：`perfstage init / list / run / report`，退出码 0/1/2/3 可被脚本消费。
- **MCP 工具**：`initialize_performance_workspace`、`list_performance_scenarios`、`prepare_performance_test`、`run_performance_test`、`analyze_performance_trace`、`finalize_performance_test`。
- **指标**：`hitches`、`blockMs`、`launchMs`、`memoryMB`，全部来自真机 trace。
- **可信边界**：`status` 与 `gate` 分离；证据缺失降为 `partial` + `gate=unknown`，不会把不可信结果算作通过。
- **Thin Skill**：`templates/SKILL.md` 与 `examples/skills/perf-community-scroll/SKILL.md`，Skill 只调用一次工具。
- **产品定位**：见 README「产品定位与边界」——平台负责驱动、采集、分析、报告；项目负责场景与 Skill；Runner 不解析 `SKILL.md`。

## 验收证据

- 真机矩阵：2 个场景 × 3 次，6/6 `completed`，全部跑在同一固定 `dist/` 构建上。
- 机器可读记录：`docs/m3-takes.json`。
- 结果与验收对照：`docs/m3-validation.md` §2 / §3。
- 已知排除项（不计入矩阵）：宿主侧 `xctrace` 保存崩溃、系统级 Jetsam，归因见 `docs/m3-validation.md` §5 与 `openSpec` 归档的 `close-out-m3-validation`。
- 自动验证：`npm run build` 通过；`npm test` 41 个文件 / 368 个用例通过。

## 不兼容变更

1. **移除诊断配置字段。** `prepare_performance_test` 顶层的 `diagnosticOverrides` 与 `adHocPlan.diagnostics` 已删除。这些字段此前被接受但从未生效；现在传入会得到校验错误，而不是静默忽略。
2. **`adHocPlan` 与场景 YAML 的顶层改为严格解析。** 未声明的顶层键会报错或导致场景加载失败（包括 `diagnostics`）；`app`、`device`、`preconditions`、`warmup` 内部仍保持宽松。
3. **`list_performance_scenarios` 不再返回 `diagnostics`。** 输出只保留场景标识、名称、Bundle ID、动作数、指标与分析重点。
4. **`plan.json` 不再写入 `diagnostics`。** 历史运行目录不受影响，报告仍可正常读取。

迁移方式：删除调用参数或场景 YAML 中的诊断字段即可，没有数据迁移。历史 `plan.json` 需要先删除 `diagnostics` 块，才能作为 `perfstage run --plan` 的输入。设备日志、Crash 差集与生命周期证据仍按既有行为采集；网络抓包与失败截图不在 v0.1 范围。

## 已知限制

- **阈值仍是占位值。** `hitches` warn 5 / fail 15 远低于真机滑动实际值，因此矩阵里 `gate=fail` 属预期；重标定要等基线设施（阶段 C）。
- **`hitches` 是卡顿帧数**，不是 sparse hang 事件数。
- **Crash 差集是设备级的。** 系统级 Jetsam 会被当作新增 Crash，需要人工归因。
- **trace 体积与保存耗时偏高**，单次 Take 的墙钟时间主要在保存阶段。
- **`report.json` 的 `lineCount` 比实际日志行数多 1。**
- **不采集网络抓包，也不生成失败截图**（见不兼容变更 1）。
- **没有历史索引、基线与趋势**；只有单次报告与阈值门禁。
- **MCP 版本在进程启动时读取 `package.json`。** 部署时不要把 `dist/` 与 `package.json` 拆开，否则进程会以 `missing a version field` 退出。
